# Чтение результата через gRPC

Пример использует Go 1.25 или новее. Сгенерированные файлы уже включены. PostgreSQL, Kafka и запущенный сайт для этого примера не требуются. `FixtureReader` предоставляет заранее подготовленные данные в памяти.

В одном терминале из каталога приложения запускается сервер.

```bash
go run ./cmd/checks -server
```

В другом терминале из того же каталога читается результат.

```bash
go run ./cmd/checks -audit a-41
```

Аудит `a-41` имеет результат `r-41` с проблемой `missing-content-security-policy`. Аудит `a-42` известен, но ещё выполняется, поэтому чтение результата возвращает `ErrNotReady`. Другие идентификаторы возвращают `ErrNotFound`.

Проверки запускают сервер на свободном локальном TCP-порту.

```bash
go test ./...
```

Для повторной генерации после изменения _checks/v1/checks.proto_ служит скрипт.

```bash
bash generate.sh
```

Он требует `bash`, `curl`, `unzip` и Go. Скрипт поддерживает macOS и Linux на arm64 и x86_64. Он загружает `protoc` 31.1 и локальные генераторы `protoc-gen-go` 1.36.8, `protoc-gen-go-grpc` 1.5.1 в _.tools_. Этот каталог не входит в исходники. Для обычного запуска генерация не нужна.

Тип `ChecksClient` показывает делегирование существующих `Start` и `State` HTTP-части и нового `Result` RPC-части. Сам HTTP-сервис в этом минимальном примере не запускается. Его поведение сохраняется в приложении аудита. `TestHybridKeepsStartAndState` проверяет выбор частей адаптера с тестовой реализацией HTTP-интерфейса.
