# Локальный стенд проверки доступа

Пример требует Go. Готовая команда `go run ./cmd/setup` создаёт локальные сертификаты в _certs_ и настройки в _local.env_. Сертификат доверия не устанавливается в систему. Сервис отчётов предоставляет фиксированные отчёты в памяти.

В первом терминале из каталога примера запускается gRPC-сервис с TLS.

```bash
go run ./cmd/setup
. ./local.env
go run ./cmd/secure -server
```

Во втором терминале запускается HTTPS API.

```bash
. ./local.env
go run ./cmd/secure -api
```

В третьем терминале выполняется служебный запрос и запрос пользователя.

```bash
. ./local.env
go run ./cmd/secure -audit a-1
user_token=$(go run ./cmd/secure -token -user 1)
curl -sS --cacert certs/ca.crt https://localhost:8443/audits/a-1/report \
  -H "Authorization: Bearer $user_token"
```

Для отказов по служебному праву служит переопределение `SERVICE_TOKEN` у клиента. Сервис проверок распознаётся, но не может читать отчёты.

```bash
SERVICE_TOKEN="$CHECKS_SERVICE_TOKEN" go run ./cmd/secure -audit a-1
SERVICE_TOKEN='unknown-service-token' go run ./cmd/secure -audit a-1
```

Аудит `a-1` принадлежит пользователю `1`, аудит `a-2` пользователю `2`. HTTP-заголовок `X-User-Id` не определяет пользователя. Проверка использует подписанный JWT с ограниченным алгоритмом, сроком действия, издателем и аудиторией.

Тесты запускают gRPC на свободном локальном TCP-порту и проверяют разрешённый вызов, неизвестный токен, отсутствие права, TLS, владельца и диагностику.

```bash
go test ./...
```

Файлы Protobuf уже сгенерированы. При изменении схемы повторная генерация выполняется через `bash generate.sh`, как в примере синхронного взаимодействия. Скрипт закрепляет версии генераторов и поддерживает macOS и Linux на arm64 и x86_64.
