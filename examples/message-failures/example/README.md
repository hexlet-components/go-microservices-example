# Политика ошибок асинхронной обработки

Пример требует Go 1.25 или новее. Обычный запуск использует подготовленные записи и тестовые функции вместо внешних сервисов.

```bash
go run ./cmd/demo
go test ./...
```

`Processor.Process` повторяет временный отказ `Apply` до `MaxAttempts`. После исчерпания попыток он возвращает ошибку без фиксации. Нарушение формата вызывает публикацию оболочки DLT, затем фиксацию исходной записи. Публикация и фиксация остаются отдельными операциями, поэтому возможен повтор DLT.

Файл _kafka.go_ содержит реальные адаптеры `KafkaPublish`, `KafkaCommit` и цикл `Consume`. Клиент для этого цикла должен использовать `DisableAutoCommit`, `BlockRebalanceOnPoll` и читать по одной записи. При возврате ошибки владелец процесса закрывает клиент через `CloseAllowingRebalance` и завершает процесс.

Для интеграционного теста нужен доступный брокер Kafka.

```bash
KAFKA_BROKERS=127.0.0.1:19092 go test -run TestKafkaDeadLetterAndSourceProgress -v
```

Тест создаёт уникальные топики с префиксом `gm.failures.` и собственную группу. Он не меняет существующие топики или позиции групп. Он подтверждает две копии DLT с одинаковым идентификатором DLT и исходными координатами при прерывании шага исходной фиксации. Без `KAFKA_BROKERS` этот тест пропускается с сообщением, остальные проверки выполняются.
